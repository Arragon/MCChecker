## 4. 缺口与 ADR

| 缺口 | 影响 | 处置 |
|---|---|---|
| XML 路径：原型索引路径 vs MD namespace+occurrence | 绑定/提取/导出/历史路径显示与定位 | ADR-007；M11-03 证明双表示 |
| 工作区权限文案/命名 | 切 W 后权限是否变化；文案不统一 | ADR-008；全局权限、统一“工作区” |
| 配置域 W-only `spaceStore` | 同 W 两机型可能串配置/文件 | ADR-009；实现 W+P + fixtures |
| iframe/`MCCV3Host` vs 单应用 | 第二站点/第二文件库风险 | ADR-010；原生视图 + 等价能力 |
| 50/页 vs 50/100 | 提取分页/全计划选择 | ADR-011；默认 50、100 可选 |
| 原型独立文件库/空间设置 | 与“唯一文件入口/宿主工作区管理”冲突 | 保留为原型演示；正式 UI 只走宿主 |

## 5. 验收方式

- 每张前端/全栈卡：在 PR 里附对应屏的 Playwright/headless Chrome 截图或 DOM 断言；`<title>ALL PASSED (n)</title>` 只证明前端单元页，不替代屏对照。
- M15-04：按本表逐屏跑 1366/1920/375/768、键盘 only、模态焦点/ESC、空/错/加载、3k 分页、冲突恢复；缺口单开卡，不伪 PASS。
- 任何 UI 与原型不一致：先查本表/ADR；需要改原型的，先改原型并更新本表，不允许实现卡静默偏离。
