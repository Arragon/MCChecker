# MCChecker 功能实现变更说明

| 项 | 内容 |
|---|---|
| 文档状态 | 与 [`MCChecker_REDESIGN_SPEC.md`](MCChecker_REDESIGN_SPEC.md) 配套的变更清单，尚未实现 |
| 目的 | 重构保留全部原有功能（规范 §2.1 F01–F28），但部分功能的**实现形式**不是最优。本文逐条记录“原实现 → 新方案”，说明理由、兼容方式与验收用例，避免实现时被当作“顺手改掉”的行为变化 |
| 编号 | `C01`… 在主规范、代码注释与 PR 描述中引用 |
| 原则 | 只改实现形式，不改业务语义：数据仍在原位置、原格式；用户能做的事一件不少；变化都能在界面上被看到并解释 |

阅读方式：每条包含 **原实现**（代码事实）、**问题**、**新方案**、**兼容**、**验收**（主规范 §16.2 用例编号）。“不改变”一栏列出刻意保持原样的部分。

## 一、总体与导航

### C01 技术栈：NiceGUI 服务端渲染 → 标准库 HTTP + 原生前端
- **原实现**：NiceGUI（FastAPI/Starlette/Uvicorn/Vue/Quasar）把 UI 组件树保存在服务端，交互经 WebSocket 回调；APScheduler 做定时。
- **问题**：需联网安装约 20 个包；3.9.11 下无法导入（`storage.py:355` `str | None`）；会话内存随在线人数增长；大文件每节点多个服务端元素。
- **新方案**：`http.server.ThreadingHTTPServer` + JSON API + `app/web` 原生前端；`threading` 调度器替代 APScheduler（规范 §3、§10）。
- **兼容**：数据目录与格式不变；旧下载链接与 `/record_view` 链接保留兼容（规范 §7.12）。
- **验收**：规范 §16.6、§16.7。

### C02 导航：三套并存 → “侧栏 = 去哪 / 标签 = 打开了什么 / 分段 = 看哪一面”
- **原实现**：顶栏 6 个纯图标按钮（上传、URL、搜索、更新设置、绑定、工具、审阅）+ 标签条 + “返回上一页”历史栈 + 文件页内“版本历史/修改记录/版本对比”按钮；同一个文件会打开 4 个标签（文件、历史:、对比:、修改记录:）；“下载文件”在文件页出现两次。
- **新方案**：侧栏带文字的 5 个导航 + 文件列表 + 外部工具；顶栏只放机型、搜索、任务、身份；**一个文件一个标签**，标签内分段“结构 / 历史版本 / 对比 / 修改记录”；去掉自建返回栈，路由完整写入 URL，由浏览器前进/后退；下载只在文件头部出现一次。
- **兼容**：所有旧入口都有新位置（规范 §9.2 迁移对照表）；标签上限仍为 15。
- **验收**：UC-02、UC-14、UC-42、UC-43。

### C24 标签状态存放位置与淘汰规则
- **原实现**：标签与返回栈存在 NiceGUI `app.storage.user`（服务端 `.nicegui/` 文件）；超限时淘汰最早打开的非活动标签，不管是否有未保存输入。
- **新方案**：存浏览器 `localStorage`（按机型）；淘汰“最久未使用且无未保存修改”的标签并 Toast 告知；有未保存修改的标签关闭需确认；URL 可分享。
- **兼容**：旧标签状态不迁移（属于会话状态，非业务数据），首次进入落到速览。
- **验收**：UC-42、UC-43。

### C18 身份展示
- **原实现**：顶栏徽标只区分“管理员 / 游客”，部署者在本机访问显示为“游客”，并重复显示两次 IP（与 know-how“不显示 IP”矛盾，截图 `before/01-home-overview.png`）。
- **新方案**：角色标签组合显示“部署者 · 管理员 / 部署者 / 管理员 / 成员 / 访客”；点击身份打开弹层，列出 4 项能力（✓/✕）与当前识别地址（带复制按钮，用于请部署者登记）。顶栏不再显示 IP。
- **验收**：UC-01、UC-34、UC-44。

## 二、查看与查找

### C03 结构树渲染
- **原实现**：每个节点创建一组服务端 `ui.row/ui.html/ui.icon/ui.button`；默认全部展开；行高约 30 px；8 色循环缩进线；`user-select:none` 导致值不能选中复制。
- **问题**：数千节点即明显卡顿；视觉噪声大。
- **新方案**：服务端下发扁平先序数组，前端虚拟滚动（只渲染可视行），折叠时按子树大小跳过；≤ 3 000 节点仍默认全部展开（保持习惯），更大文件默认展开前两层并提供“展开到第 n 层”；单色细引导线；行高 28 px；值可在详情面板选中复制。
- **不改变**：节点的显示内容（标签 = 值、`@属性`、`#text`、`[i]`）、param 节点的行内描述与范围语义。
- **验收**：UC-02、UC-07。

### C04 大 XML 不再丢属性
- **原实现**：≥ 200 KB 的 XML 只保留 `description/editPrivilege/default/min/max/incMin/incMax` 属性（`parser.py:12-13`），其余属性直接不进入解析结果。
- **问题**：大文件查看、搜索、对比、审阅生成都会漏属性；审阅生成的新文件会**丢失**这些属性（数据错误）。
- **新方案**：始终完整解析；用工具栏“显示属性”开关控制是否展示属性行（默认显示，与旧版小文件一致）。性能由 C03 解决。
- **验收**：规范 T-05 验收、UC-06。

### C05 节点操作：悬停按钮 + 弹窗 → 选中 + 详情面板
- **原实现**：修改备注按钮只在行悬停时出现，点击后弹窗；参数范围靠行内“展开参数范围”按钮；没有键盘路径；看不到完整长值。
- **新方案**：点击/键盘选中行 → 右侧详情面板显示完整值（复制）、参数信息（默认/最小/最大与含/不含、越界警告）、属性列表、显示路径/绑定路径（复制，可直接粘贴到变量绑定与 DL 绑定）、收藏按钮、待审建议与提交表单。树内键盘：↑↓←→、Enter、S。面板可隐藏，窄屏为抽屉。
- **验收**：UC-03、UC-04、UC-13。

### C17 全局搜索
- **原实现**：对每个文件返回过滤后的整棵树并逐个渲染；父节点命中时计数为 0，可能显示“未找到”（`searching.py:40-45`）；入口是弹窗输入后新开“搜索:”标签（每次搜索一个新标签）。
- **新方案**：服务端返回扁平命中列表（文件、路径、标签、值、备注、匹配字段），按文件分组、关键字高亮、分页 200 条；每个命中节点计 1；Ctrl+K 命令面板可跳转文件或发起搜索；搜索为单例标签，关键词写入 URL；支持限定单个文件。
- **不改变**：匹配范围（名称、值、收藏备注，大小写不敏感，仅当前版本）。
- **验收**：UC-25、UC-26。

### C16 速览
- **原实现**：每个收藏一张卡片，按文件折叠分组，卡片左边框循环 10 种颜色；隐藏 DOM 标记 + `querySelector` 拼接路径删除卡片（存在注入风险）。
- **新方案**：按文件分组的紧凑表格（变量 / 当前值 / 备注 / 路径 / 操作）；当前值与收藏时值不同时显示“收藏时为 x”；取消收藏 Toast 带“撤销”；“定位”直接打开文件并选中节点；右栏补充最近更新、待审概况、定时状态（只读信息，不做 Dashboard）。
- **不改变**：实时取值、“未检测到，请检查”、源文件不存在时归入单独分组并在恢复后回到原组、备注所有人可编辑、按文件清空。
- **验收**：UC-08、UC-10～UC-12。

### C32 收藏由服务端生成快照
- **原实现**：前端把 label/value 与整棵子树快照提交给存储层。
- **新方案**：前端只提交 `{file, id}`，服务端从当前版本取值并生成快照；被父级覆盖返回 `FAVORITE_COVERED`。
- **兼容**：`favorites.json` 格式不变。
- **验收**：UC-08、UC-09。

## 三、修改建议与审阅

### C06 建议的节点定位
- **原实现**：`node_key` = 渲染时过滤后子节点的下标链（`viewer.py:207,400`），审阅时套到最新完整树上（`reviewing.get_node_by_key`）。
- **问题**：在筛选状态下提交、或隐藏了 param 元属性时，下标与完整树不一致 → **可能改错节点**；文件更新后旧下标也会漂移。
- **新方案**：建议保存 `locator`（同一内容内唯一，XML 用同名兄弟序号、JSON 用 JSON Pointer）+ `source_sha256` + 原值；提交时若文件已变化返回 `SOURCE_CHANGED`；JSON 节点检查建议值类型（int/float/bool/null）。
- **兼容**：`edit_remarks.json` 只新增可选字段；旧建议（无 locator）按旧节点 ID 唯一匹配且原值一致才允许通过，否则只能驳回，并在审阅页标“旧版”。
- **验收**：UC-13、UC-23。

### C07 审阅流程
- **原实现**：必须为页面上**所有**待审节点做出选择才能提交（`review.py:53-59`）；选择保存在渲染闭包，切换标签即丢失；无源文件变化检测；重复点击可能重复生成。
- **新方案**：左侧节点列表 + 右侧详情；选择即存本地草稿（刷新不丢）；**按文件提交，可只提交已决定的节点**，其余保持待审；提交带源文件指纹，变化则拒绝并刷新；值已变化或无法唯一定位的节点只能驳回；`request_id` 幂等；提交前确认框列出“原值 → 新值”。
- **不改变**：管理员才能审阅；一个节点只能通过一条建议、同组其余自动驳回；生成**新文件**、不覆盖原文件；记录审阅人与时间。
- **验收**：UC-20～UC-24。

### C08 审阅生成的新文件
- **原实现**：在（可能丢属性的）展示树上改值，再把展示树序列化成 XML/JSON（`reviewing.serialize_tree`），并 `ET.indent` 重新排版；JSON 类型由字符串回推。
- **问题**：可能丢属性、丢注释、改变类型、改变格式。
- **新方案**：在**原文**上解析（保留注释与处理指令、注册原命名空间前缀），只修改选中的节点后输出；输出再解析，与原文逐节点比较，差异必须恰好等于本次修改，否则拒绝生成（`REVIEW_UNSAFE`），不写任何文件。
- **已知限制**：标准库输出会统一引号与空元素写法，业务值不受影响；在确认框中说明。
- **验收**：规范 T-16 测试清单、UC-20。

## 四、文件导入、版本与对比

### C09 访客导入：仅会话可见（不可用）→ 临时文件
- **原实现**：访客上传/URL 导入解析成功后只提示“仅会话可见”，随后按文件名打开标签——实际读取的是服务器同名文件（不存在则报错），上传内容被丢弃（`home.py:1163-1170`）。
- **新方案**：上传内容存入 `data/temporary/<token>/`，只有上传者（同 `mc_cid` cookie 且同 IP）可访问，默认 24 小时过期；临时标签显示“临时 · 仅自己可见”，可查看结构与参与对比；不会回退读取同名服务器文件。部署者仍可选择“保存到服务器”。
- **验收**：UC-28。

### C26 文件名规则统一
- **原实现**：更新源文件名只允许 `[A-Za-z0-9-_.]`（`storage._sanitize_config_filename`），而上传保存的文件名几乎不校验（可含中文，也可含危险字符）。
- **新方案**：所有入口统一 `validate_filename`：允许中文等 Unicode，拒绝路径分隔符、Windows 非法字符与保留名、控制字符、`.`/`..`、超长。
- **兼容**：已存在的旧文件名照常读取；仅在新建/改名时校验。
- **验收**：规范 T-02 验收。

### C10 对比：四种模式下拉 → 统一的“基准 / 目标”选择器
- **原实现**：先选四种模式之一，再按模式出现不同的选择器/上传按钮；从历史版本点“与当前对比”只打开对比标签，**没有带上所选版本**，默认对比第一个归档（`history.py:158-181`）；结构化差异逐行渲染，不能筛选。
- **新方案**：两个同构选择器（当前 / 历史版本 / 修改记录 / 已上传 / 上传本地文件…）+ 交换按钮；从历史与记录列表进入时自动预填两侧并运行；差异摘要卡片可点击筛选类型；结构化差异表支持文字筛选、“仅绑定变量”、“定位”到结构树；文本差异可折叠、复制、下载 `.diff`。
- **不改变**：旧四种场景全部可完成（另外支持记录 vs 记录等任意组合）；颜色语义绿/红/橙/紫。
- **验收**：UC-15～UC-19。

### C11 结构化差异的比较键
- **原实现**：以“标签路径”为键（`parser.get_all_values` + `_normalize_path`），同名兄弟节点互相覆盖，只比较到最后一个。
- **新方案**：以定位符为键，同名兄弟逐个比较；绑定匹配仍使用旧的“文件名/标签/…”路径（去掉首段后比较），旧 `bindings.json` 直接可用。
- **兼容**：历史列表若无法确认绑定版本，降级显示旧 `.diff.json` 统计并标“旧统计”。
- **验收**：UC-14、UC-18。

### C22 下载
- **原实现**：先用带探测头的请求检查，再让浏览器二次请求下载；失败弹出持久对话框。
- **新方案**：一次 `fetch` 取回后保存，失败 Toast 显示原因并提供“重试”；`Content-Disposition` 使用 RFC 5987 编码保证中文文件名；历史版本下载名为版本文件名（保持）。
- **兼容**：旧 `/api/file-download` 与探测头行为保留（规范 §7.12）。
- **验收**：UC-46。

## 五、更新源、定时与修改记录

### C12 更新流程
- **原实现**：下载成功就保存（`scheduler.run_single_update`），不校验内容；保存时先把当前文件 move 到归档再写新文件；内容相同也产生一个“无变更”归档；手动更新在请求线程同步执行（阻塞界面）；手动与定时可同时对同一文件执行。
- **问题**：HTTP 200 的错误页会替换有效配置；中断会留下缺失当前版本；历史被大量“无变更”版本淹没；长时间阻塞。
- **新方案**：下载（scheme/地址/大小/重定向策略）→ 解析校验 → 根节点指纹一致 → 内容 sha 相同则 `unchanged`（**不归档**，只记录检查时间与结果）→ 锁内复制归档后原子替换 → 写 `update_status.json`。全部以后台任务执行，顶栏显示进度，相同任务防重入（`BUSY`）。
- **兼容**：`config_mapping.json` 不变；新增可选 `update_status.json`。“无变化”不再生成历史版本属于有意的行为改变（历史只记录真实变化），最近检查时间改在“更新源”状态列显示。
- **验收**：UC-31、UC-32。

### C13 修改记录
- **原实现**：修改记录页面对每个打开它的部署者客户端按定时间隔再拉一次（与调度器重复）；每次拉取都新建记录文件，即使内容相同；查看记录要打开独立页面 `/record_view`，链接不带机型。
- **新方案**：只由调度器与“立即拉取”按钮（后台任务）触发；内容与最新一条相同则不新建；查看记录在文件标签内以 `version=record:<名称>` 打开，复用结构树、对比与下载。
- **兼容**：`records/` 目录与命名不变；旧 `/record_view` 链接 302 到新位置。
- **验收**：UC-30、UC-46。

### C14 定时更新
- **原实现**：界面有“小时/天”单位选择但未参与保存（`management.py:66`），只按数字当小时保存；看不到下次执行时间与上次结果。
- **新方案**：单位换算后仍以 `interval_hours` 存储（“天”= 24 的倍数），回显时自动选择单位；显示下次执行时间与上次执行结果（`schedule.json` 新增可选 `last_run`）。
- **验收**：UC-33。

### C29 设置保存后局部刷新
- **原实现**：IP 表、管理员等保存后 `location.reload()` 整页刷新；工具、绑定保存后列表不刷新。
- **新方案**：保存成功后只刷新对应列表与受影响的身份信息；字段级错误显示在输入框下方并保留输入。
- **验收**：UC-34～UC-36。

### C31 变量绑定的编辑与校验
- **原实现**：只能新增或删除绑定组；新增时可以保存空变量列表；同名组直接覆盖。
- **新方案**：可编辑已有组（改名、增删变量）；至少 2 个有效变量；改名不得与已有组重名；行内显示格式标签与绑定路径，可从详情面板复制绑定路径填入。
- **兼容**：`bindings.json` 格式不变。
- **验收**：UC-35。

### C23 外部工具
- **原实现**：`window.open("{url}")` 字符串拼接（注入风险）；名称可重复；URL 不校验。
- **新方案**：渲染为 `<a target="_blank" rel="noopener noreferrer">`；只允许 http/https；名称唯一。
- **验收**：UC-36、规范 §16.8。

## 六、DL 快捷计算

### C15 DL 计算的编辑、计算与结果
- **原实现**：
  - “修改/保存/取消”把 `editing` 标志写进共享 `dltool_config.json`——一个人进入编辑，所有人都处于编辑态；“应用并提取”绑定会立即保存，“取消”撤不回；任何人都能保存。
  - `inp.value or 0.0`：清空的范围被保存为 0；`or 1.0` 让真实的 0 被替换。
  - 正向计算把越界输入**静默丢弃**；PP 反向结果按过滤前的下标回填目标值，可能错位。
  - 系数提取失败的字段保持默认 0 并提示“已提取”。
  - 求根只做等距采样 + 变号二分，漏掉切触重根（如 (x−3)² = 0）；多解时默认选“绝对值最小”的解当作“最优”。
- **新方案**：
  - 参数修改进入**本地草稿**，所有人都可用草稿试算（服务端按传入参数计算，不写文件）；只有部署者能“保存为配置”，带 `If-Match` 防止覆盖他人修改；“放弃修改”只丢本地草稿。
  - 空值保存为 `null`，0 就是 0；非法数值在输入框标红且不写入。
  - 结果逐行携带 `input_index`，越界行标注“x/y 超出范围”而不是消失。
  - 提取先预览（字段、系数、当前值、提取值、状态），缺失/非数值字段保持原值，用户确认后“应用到草稿”。
  - 求根增加切触重根、端点与常数函数检测，结果标注为“在范围内检测到的候选根”；多解时由用户在每行选择采用的解，不自动选“最优”；结果可复制/下载 CSV（使用用户的选择）。
- **兼容**：`dltool_config.json` 字段不变；`editing` 读取时忽略、保存时写 `false`。
- **验收**：UC-37～UC-39，前端测试页 DL 用例，规范 T-20。

## 七、权限、数据安全与多用户

### C19 服务端强制权限
- **原实现**：权限主要靠隐藏按钮；机型增删改、DL 保存、绑定“应用”等路径没有部署者校验；部分对话框只在打开时检查。
- **新方案**：规范 §4.2 矩阵由服务端在每个请求执行；写接口要求自定义请求头（防跨站伪造）；前端按钮禁用只用于提示原因。
- **不改变**：部署者/管理员的判定规则、IP 表与管理员名单按机型保存、收藏与收藏备注对所有人开放、所有人可提交修改建议。
- **验收**：§16.3、UC-44。

### C28 写入可靠性
- **原实现**：JSON 直接覆盖写；损坏的 JSON 读成空列表，下一次保存会把数据清空；无锁，并发修改互相覆盖；归档同秒重名会覆盖。
- **新方案**：同目录临时文件 + fsync + 原子替换；每机型锁覆盖整个读改写；损坏文件进入只读保护并报错（`CORRUPT_DATA`），不再被覆盖；归档/记录/生成文件独占创建、同秒追加 `_2`。
- **兼容**：文件格式与位置不变。
- **验收**：规范 T-02、T-03。

### C20 删除文件
- **原实现**：物理删除当前文件、整个归档目录与记录目录（`rmtree(ignore_errors=True)`，部分失败也提示成功）；确认框一次点击即可。
- **新方案**：移入 `data/recovery/` 并写清单（含被移除的收藏/绑定/建议引用，便于恢复）；确认框说明影响数量与恢复方式，并要求输入文件名确认。
- **不改变**：管理员才能删除；同时清理映射、收藏、绑定变量与建议。
- **验收**：UC-11、UC-41（机型同理）。

### C27 机型删除与复制
- **原实现**：删除机型时可选“同时删除全部数据”（物理删除）；复制机型时连缓存一起复制。
- **新方案**：删除机型一律把数据目录移入恢复区（不再提供物理删除开关），需输入机型标识确认；复制不再包含可重建的缓存。复制范围其余保持原样（不复制修改记录、建议、IP 表、管理员名单）。
- **验收**：UC-41。

### C30 旧布局迁移
- **原实现**：每次启动对旧 `data/*` 执行 `shutil.move`，失败只打警告，可能半迁移。
- **新方案**：复制 → 校验 → 旧条目移入恢复区；失败回滚副本、继续使用旧位置读取；幂等。
- **验收**：规范 §16.5。

### C21 多用户变更感知
- **原实现**：每个客户端每 1 秒扫描文件列表签名、每 1 秒扫描收藏、每 0.3 秒检查标签；他人修改时直接重绘（可能打断操作）。
- **新方案**：每 10 秒（页面可见时）请求一次内存修订号；变化时只刷新受影响的列表；正在查看的文件被他人更新时显示“此文件已被更新…［重新加载］”横幅，不自动替换内容；本地写入后同步修订号，避免误报。
- **验收**：UC-40。

### C25 端口与配置
- **原实现**：`run.py` 定义了 `MCHECKER_PORT` 读取函数但被注释，实际固定 50002；README 写 50001。
- **新方案**：`MCHECKER_PORT` / `--port` 生效，默认 **50002**（保持现网端口不变）；非法值启动失败并提示；新增 `--data-dir`、受信代理等配置（规范 §3.6）。README 同步改为 50002。
- **验收**：规范 T-04。
