# ADR-012–020 · V3.1/M16 同步域、采集器与发布边界

- 状态：M16-00 复核后 `Accepted`（2026-11-02）；M16-01 如发现实际代码冲突，先改 ADR 再开工下游卡。
- 范围：只解决 M16 的跨卡不可逆决策；不替代各卡的具体实现方案。
- 原则：Linear 卡面/执行索引是范围与验收事实源；V3.1 MD 是服务端行为事实源；HTML 是界面/交互事实源。实现卡不得自行选边；任何变更必须同步 `docs/MCChecker_V3.1_PLAN.md`、本文件与相关 Linear 卡。

## ADR-012 · 分支与代码基线

**冲突**：M16 卡面写首次源码评估为 `main@429dafaa`，但 V3.0 的 M9–M15 只在 `feat/mc-v3@1c10582`；M16-00 冻结时 main 已到 `b964c6e`（计划快照后新增 3 个非 V3 的 UI 提交），feat/mc-v3.1 领先 main 146、落后 3，main 没有 workspace/FileResource/D0-Bn-rn 代码；M15 豁免文档已作为 `df96271` 提交进入 feat/mc-v3.1，PR #193 仍 open。

**决议**：
- 先把 M15 豁免文档作为 docs-only chore PR 合入 `feat/mc-v3`，再从其 tip 创建 `feat/mc-v3.1`。
- 不 rebase、不 merge main；M16-00 记录 `origin/main@b964c6e`、`feat/mc-v3@1c10582`、`feat/mc-v3.1@6b018a7`；main 后续移动时由 M16-01 审计，不把 main 当 V3 基线。
- 卡分支 `mc-v31/<卡号>-<slug>`；PR base 恒为 `feat/mc-v3.1`；M16 收口后才开 `feat/mc-v3.1 → main` 汇总 PR。
- V3.0 是否合 main 是独立发布决策，不作为 M16 开工前置；若负责人决定先合 main，必须重新冻结基线并重跑证据。

**下游**：M16-00（记录基线）、M16-01（审计 main/feat 差异）、M16-42（最终发布）。

## ADR-013 · API 命名与孤儿接口归属

**冲突**：卡面多处写 `/api/v1/w/{wid}/...`，仓库实际 v3 前缀是 `/api/v3/workspaces/{wid}/...`；`source-checks`、catalog picker、`session-candidates`、连接创建没有明确归属卡。

**决议**：
- 新 API 统一 `/api/v3/workspaces/{wid}/...`；旧 `/api/v1/p/{pid}/sources` 保留只读兼容，不新增 v1 写入口。
- 归属：`source-check` → M16-24；catalog picker → M16-16 + M16-30；`session-candidates` → M16-19 + M16-30；connection create → M16-04 + M16-30。
- 所有写操作带 `If-Match`/expected revision/`Idempotency-Key`；服务端强制权限，前端隐藏按钮不算授权。
- v3 列表包络由 M16-01 冻结；不得只返回 `items` 而省略分页/查询修订信息。

**下游**：M16-05/08/10/11/12/23/30/32–36/38。

## ADR-014 · W/P 作用域与术语

**冲突**：卡面引用 `WorkspaceContext`、`PathResolver`，仓库没有这两个类；实际是 `app/services/workspace_context.py::resolve/assert_profile`、`app/services/workspace_catalog.py::workspace_root/profile_root`、`app/core/storage.py::use_workspace/use_profile`。

**决议**：
- 不新建卡面不存在的同名类；所有卡引用实际符号。
- 如多模块需要统一路径，M16-01 可加一个薄封装（建议 `app/services/sync_paths.py`），但不得叫 `PathResolver` 或复制 workspace 解析逻辑。
- Workspace 是业务数据边界，Profile 在 W 内；来源、连接、凭据、run、候选、观测都带 W/P；全局身份/权限不随空间分裂。
- 旧 legacy 工作区没有 `data/workspaces/default`；新增 workspace 级路径必须定义 legacy 落点，并同步 `tests/conftest.py::DATA_SUBDIRS`、`scripts/backup_v3.py`、`scripts/migrate_v3.py`。

**下游**：M16-04/05/07/08/11/23/30/37。

## ADR-015 · M15 豁免与发布谱系

**冲突**：INH-2161（M15-06）已 Done，但 M16-42 仍把它登记为 blockedBy；2160/2161 是负责人试用后的书面豁免，不是外部证据 PASS。

## ADR-016 · 06/37 迁移边界

**冲突**：M16-06 提议 `scripts/sync_migrate.py`，M16-37 提议 `sync_migration_dry_run.py` + `sync_upgrade.py`；两卡都改迁移数据与脚本，容易形成两套算法。

**决议**：
- 只留一套代码：`app/services/sync_migration.py` + `scripts/sync_migrate.py`，子命令 `plan|execute|verify|rollback`。
- M16-06 只做 plan/dry-run/映射/幂等计划；M16-37 才 execute/backup/还原/回退；`sync_upgrade.py` 如保留，只作执行入口，不复制算法。
- 迁移只做加法：不删除旧 JSON/归档/记录；旧文件/record/archive SHA 前后一致；未知旧字段有确定结果。
- 备份覆盖 sync 数据、排除 secret root；回退前停 SDA/collector。

**下游**：M16-06/37/42。

## ADR-017 · TaskRunner 与 SyncRun

**冲突**：现有 `Task.profile` 必填、`TaskRunner._conflict_locked` 是 workspace+profile+冲突类型、`Scheduler._Plan` 键 `(W,P)`、revision 无 W 级分量；M16 需要 workspace 级 run、按连接限并发、幂等/取消/重试。

**决议**：
- 新增 `sync_run` 任务类型；`Task` 正式携带 workspace，W/P 进入不可变 payload。
- 网络/浏览器在锁外；提交前在 W/P 锁内重验 source/binding/policy/epoch/target head/read_set。
- `Idempotency-Key` 作用域到 run；同 key 同参数返回同 run，异参数拒绝。
- 只重试 `failed`/可恢复 `blocked`；新 run 带 `parent_run_id`，不改写旧 run 终态。
- 取消保留已提交项；不新增不受管 ThreadPool/手搓写盘线程；手动与定时共享同一互斥；不自动 publish。

**下游**：M16-11/12/23/24/35/39。

## ADR-018 · SecretStore 与凭据授权（2026-11-06 修订）

**冲突**：仓库没有 SecretStore/加密/keyring；现有权限是全局 admin，卡面又要求“独立运维授权”且不新增 WorkspaceMembership/空间角色。

**决议**：
- 用户于 2026-11-06 明确全系统仅区分管理员和访客，覆盖原“独立运维授权”要求。`integration_credentials_manage` 保留为 API 能力键，统一映射全局管理员；访客可查看安全投影，管理写入一律 403。无需 operator token，也不按登记状态增加第三类角色。
- 密文根在 `data/` 外，由部署端注入密钥；密钥与密文分离；不提供明文回退。
- AAD 绑定 `workspace + connection + generation`；密文篡改/密钥缺失/错误密钥时停用并可恢复，不读取明文。
- 密码/Cookie/CSRF/key 不进任务参数、日志、Git、Linear、业务备份、HTML、诊断 Blob、异常 trace。
- 不做 WorkspaceMembership、空间角色、第二套全站登录或独立运维身份。每次请求由现有身份解析和服务端权限矩阵强制授权；`deployer` 历史能力键仅兼容管理员同义，不提供独立权限。

**下游**：M16-18/19/30/34/38/42。

## ADR-020 · 外部证据与不可伪造 PASS

**冲突**：M16-02/20/41 需要真实 SDA 内网、真实闲置窗口、真实登录页/CA/代理；M16-20 的卡面要求有内网验收，但 M16-41 才做完整闭环，形成证据倒挂。当前真实 SDA 环境暂时不可得。

**决议**：
- 证据分层：E1 合成 fixture 可离线；E2 真实登录/心跳实验；E3 真实 idle/重登；E4 Windows/Linux/离线 Chromium；E5 两平台断网安装/回退。
- 02/20/41 分三阶段：02 协议 canary；20 单连接 idle canary；41 全链路真实闭环；20 不得用 41 的结果倒推 Done。
- 未取得 E2–E5 时，02/20/41/42 保持 `BLOCKED-EXTERNAL`；42 不得在 41/20 未 Done 时 Done。
- 状态词表：`PASS / FAIL / BLOCKED / NOT-TESTED / ACCEPTED-WITH-EXEMPTION / KNOWN-LIMITATION`；HTML/mock/CI runner/负责人豁免不能冒充 PASS。
- PASS 证据包必须含：卡号、状态、环境、命令、原始输出、commit/artifact SHA、前后 hash、时间/执行人、已知限制；真实凭据/业务原文不入库。

**下游**：M16-02/14/20/41/42。
