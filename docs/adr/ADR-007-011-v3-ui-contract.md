# ADR-007–011 · V3 原型与后端契约的界面/身份决议

- 状态：M9-00 初版（2026-10-29），M9-01 契约复核后冻结。
- 范围：只解决 INH-2117 原型 HTML 与后端设计 MD 的冲突；不替代各卡的具体实现方案。
- 原则：原型 HTML 是界面/交互事实源；后端 MD 是服务端行为事实源；实现卡不得自行选边。

## ADR-007 · XML 路径身份

**冲突**：原型 `ConfigFileEngine` 使用索引元素路径（如 `/Config[1]/Parameters[1]/Key[1]`）；后端 MD 要求 namespace URI + 完整元素路径 + 同名 occurrence。

**决议**：采用双表示。UI 显示原型索引路径；服务端 locator 保存 `{namespace_uri, element_path, occurrence}` 并派生同一显示路径。M11-03（2132）必须证明：
- 不同前缀/同 URI 的 XML 能匹配同一 locator；
- 同名兄弟按 occurrence 定位；
- 显示路径与 locator 可往返；
- 失败零写入。

若无法同时满足，回到本 ADR 选择改原型或改 MD，并同步 2137/2146/2148/2152/2153 与原型。

## ADR-008 · 工作区身份与命名

**冲突**：原型配置域切换文案写“权限随当前空间切换”，代码/实际规则是全局 `isAdmin`；界面混用“工作区/工作空间”。

**决议**：全局身份与权限唯一，不随工作区切换；统一使用“工作区”。原型文案“权限随当前空间切换”视为笔误，M9-05/2142 修正并加测试。任何 WorkspaceMembership、空间内角色、私有空间/邀请都不实现。

## ADR-009 · 配置域 W+P 隔离

**冲突**：原型配置域 `spaceStore` 只按工作区保存 configs/files/snapshots，未按机型；后端 MD 要求 FixedConfig/参数/绑定/文件/审计属于 W+P。

**决议**：实现必须 W+P 隔离。配置域状态、缓存、审计、文件引用、任务、幂等键全部带 profile；补“同一工作区两个机型同名配置/文件/参数不串”的 fixtures。原型 W-only 数据模型只作演示，不照搬。

## ADR-010 · 配置域集成方式

**冲突**：原型配置域是 iframe + `MCCV3Host` 桥接；后端 MD 要求一个应用、无第二站点。

**决议**：正式实现采用原生视图 + 等价宿主能力（context/listFiles/readFile/openFile/openUploader/openFiles/openWorkspaceManager/openGlobalSearch/renderParameterTree）。iframe/桥接只作为原型打包方式，不作为正式架构。无论实现方式，必须满足：
- 唯一文件入口仍是宿主左下列表，无第二上传库；
- 工作区管理仍由宿主顶栏负责，无第二工作区管理器；
- 配置域只读/权限/错误态与服务端一致。

## ADR-011 · 提取分页与原型数据

**冲突**：原型提取 modal 固定 50 行/页并使用本地演示数据；卡面要求 50/100、3000+/50k 与真实后端。

**决议**：默认 50 行/页，100 作为可选；全计划选择/筛选/决议在分页间保持。原型数据只用于 UI 状态与交互演示，不参与 3,200/50,000 性能、并发或验收数字；2147/2148/2149 必须用真实后端 fixtures 实测。
