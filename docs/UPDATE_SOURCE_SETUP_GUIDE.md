# 从网页链接配置更新：完整操作教程

本文说明如何从网页中找到配置文件的实际来源，并在 MCChecker 中设置手动或定时更新。适用于当前 V3.2 界面，操作以管理员身份进行；访客可以查看，不能修改更新设置。

先记住一条流程：**找到真实来源 → 配置接收目标 → 测试来源 → 保存设置 → 手动更新 → 核对结果 → 再开启定时更新。**

## 1. 先判断你拿到的是什么链接

| 手里的地址或内容 | 应选方式 | 是否需要 SDA 连接 |
| --- | --- | --- |
| 直接返回 XML / JSON 配置文件的 HTTP(S) 地址 | HTTP 文件 | 不需要 |
| 直接返回 ZIP / TAR 更新包的地址 | HTTP 文件，必要时填写文件匹配规则 | 不需要 |
| 需要登录 SDA 后打开的文件页面 | SDA 文件，从连接目录选择 | 需要 |
| SDA 上的一张参数表 | SDA 表，从连接目录选择 | 需要 |
| 普通网页、文件预览页面、登录页面 | 先找实际下载请求，不能直接当文件地址使用 | 视实际来源而定 |
| 一段 cURL、HAR、Cookie 或 JavaScript | 不是更新来源输入 | 不要粘贴到下载地址 |

**当前版本不提供“输入任意网页链接，自动识别网页结构并生成抓取规则”的通用功能。** HTTP 文件只下载文件，不执行网页脚本，不自动继承你浏览器的登录状态。SDA 来源依靠已部署的采集适配器和目录，不是任意网页爬虫。

文中使用的 `https://files.example.internal`、`https://sda.example.internal` 都是说明用地址，不可直接访问。请替换成你有权访问的实际地址。

## 2. 打开正确的设置入口

1. 顶栏选择目标工作区和机型。
2. 左侧打开“配置管理”，在配置文件列表中点击需要管理的文件。
3. 进入该文件的“更新管理”。
4. 点击右上角“更新设置”。
5. 选择已有来源进行修改，或点击“添加更新来源”。

同一个“更新设置”中还可以打开“连接设置”和“工作区计划”。文件内的来源、运行记录和待处理变化只展示该文件范围；“工作区计划”仍影响整个工作区，修改前要确认范围。

如果尚未有目标文件，先通过左侧唯一文件入口导入 XML / JSON，再在配置管理中创建或关联相应配置。不要为更新另外建立一套文件库。

## 3. 从网页里找到真实下载地址

### 3.1 优先使用网页的下载按钮

1. 在原系统中打开目标文件页面。
2. 找到“下载”“导出配置”或类似按钮。
3. 如果按钮是普通链接，右键选择“复制链接地址”。
4. 在新的浏览器标签中打开，确认得到的是配置文件，而不是网站首页或登录页。
5. 确认下载文件内容与所需机型、软件版本一致。

例如，下面可能是预览页面：

```text
https://files.example.internal/viewer/123
```

而实际文件地址可能是：

```text
https://files.example.internal/downloads/MachineConfig.xml
```

仅凭 URL 后缀不能确定内容；有些无后缀地址也会返回文件，有些 `.xml` 地址可能跳回登录页。

### 3.2 找不到链接时，用浏览器网络面板定位

以下以 Chrome 为例：

1. 在有权访问的原页面打开开发者工具，选择“Network / 网络”。
2. 清空当前请求列表，必要时启用“Preserve log / 保留日志”。
3. 回到网页，点击一次下载或导出按钮。
4. 在网络面板中找到刚出现的请求。可按文件名筛选，也可查看 Fetch/XHR 和其他请求。
5. 打开请求详情，核对：
   - **Request URL**：真正请求的地址。
   - **Request Method**：是 GET 还是 POST。
   - **Status Code**：是否成功；成功状态码本身不代表文件正确。
   - **Content-Type / Content-Disposition**：是否指向文件下载。
   - **Response / Preview**：是期望的 XML / JSON，还是 HTML 登录页、业务错误。
6. 若是普通、可直接访问的 GET 文件地址，可以作为 HTTP 文件来源候选，再到 MCChecker 中测试。

不要把“Copy as cURL / 复制为 cURL”的整段命令填进下载地址。当前来源表单不解析 cURL，也不提供任意请求头、请求体或脚本编辑器。POST 导出、动态生成任务、浏览器 `blob:` 地址和依赖临时会话的请求，都不能简单改成 HTTP 文件来源。

网络面板中的请求可能含密码、Cookie、Authorization 或临时签名。不要把原始 HAR、完整带密钥 URL、截图或请求命令提交到 Git、聊天或问题单中。普通 HTTP 来源不适合把临时签名链接当作长期定时任务；应寻找稳定下载入口，或使用已有受支持的 SDA 连接。

### 3.3 浏览器能下载，不代表服务器能下载

MCChecker 在服务端获取文件，不是在你的当前浏览器标签里下载。因此需要确认：

- MCChecker 服务器能解析目标域名、连接目标网络。
- 地址不是只对当前电脑有效的本地路径、`file:` 或 `blob:` 地址。
- 来源不依赖你浏览器中已有的 Cookie、单点登录状态。
- HTTPS 证书和部署环境符合现有要求；不要通过关闭证书验证解决问题。

## 4. 方式一：普通 HTTP 文件

### 4.1 填写来源

打开“添加更新来源”，按下表填写：

| 界面字段 | 填写方式 | 示例 |
| --- | --- | --- |
| 名称 | 容易识别的来源名称 | 整机运行配置更新 |
| 机型 | 目标机型；文件内创建时通常已限定 | 当前机型 |
| 类型 | 选择“HTTP 文件” | HTTP 文件 |
| 下载地址 | 实际返回配置文件或更新包的完整地址 | `https://files.example.internal/downloads/MachineConfig.xml` |
| 连接 | HTTP 来源无需 SDA 连接 | 不选 |
| 目标类型及对象 | 根据第 6 节选择 | 当前文件，或指定软件版本的候选 |
| 启用 | 是否让该来源参与更新 | 首次可先使用“仅手动”计划 |
| 更新计划 | 建议首次选择“仅手动” | 仅手动 |

普通 HTTP 地址不能内嵌账号密码，例如 `https://user:password@host/file.xml` 不允许。当前表单没有自定义登录、Authorization 或 Cookie 输入能力；需要认证的页面请先判断能否使用 SDA 连接。

### 4.2 高级设置什么时候填写

- **修改记录链接**：上游提供独立修改记录文件时才填写，不是配置文件预览页，也不是任意网页评论区。
- **文件匹配规则（正则）**：更新包内有多个文件，需要筛选时使用；直接下载单个文件通常留空。
- **业务路径**：用于表示上游资源位置；SDA 文件和表应从目录自动填入，不要用本机磁盘路径替代。

例如压缩包里有 `MachineConfig.xml` 和其他文件，可以使用匹配规则：

```text
^MachineConfig\.xml$
```

这里填写正则表达式本身，不是 JavaScript 的 `/.../` 字面量。包内可能含目录层级，应先确认实际匹配结果，不能仅凭这个例子猜测自己的压缩包结构。确保命中的是目标配置；不能用宽泛规则混入别的机型或版本。

### 4.3 测试、保存、手动运行

1. 点击“测试来源”，验证当前填写的输入。
2. 测试失败时，保留输入并按错误提示修正；不要直接开启定时更新。
3. 测试成功后，点击保存。
4. 回到来源列表，对该来源点击“更新”，或使用当前文件的立即更新入口。
5. 在“运行记录”中检查本次状态、失败原因和详情。
6. 再按目标类型检查文件历史或“待处理变化”。

**测试成功不等于已经保存设置或更新文件。** 来源测试读取并检查输入，不替代真正更新，也不代表已经保存软件版本标准。

## 5. 方式二：需要登录的 SDA 文件或参数表

### 5.1 先确认部署支持

SDA 需要服务器侧采集器、登录流程配置和凭据存储已启用。只在界面创建一个连接，并不能自动识别任意网站的登录表单和接口。

如果提示采集器离线、凭据存储未配置或协议不匹配，应先由维护人员检查部署。真实 SDA 与本项目的模拟服务可能有不同接口；模拟环境通过不代表真实网站已经适配。

### 5.2 从网页地址识别站点地址

例如原网页是：

```text
https://sda.example.internal/files/detail?id=F-001
```

连接中填写的 **SDA Origin** 是：

```text
https://sda.example.internal
```

Origin 只包含协议和主机，不包含 `/files/detail`、查询参数或 `#` 后的内容。当前 SDA 连接要求 HTTPS、443 端口；不要填写页面完整 URL 或其他端口。

网页里的 `id=F-001` 只是说明例子，**不能假定它就是 MCChecker 目录中的资源引用**。应以当前连接实际返回的目录为准。

### 5.3 新建连接并设置登录信息

1. 文件内“更新设置” → “连接设置” → “新建连接”。
2. 填写名称，例如“SDA 配置站点”。
3. 填写正确的 SDA Origin，勾选启用并创建。
4. 在该连接上点击“更换凭据”，填写有权访问目标资源的账号、密码并提交。
5. 提交后只是创建待验证的登录信息；按界面执行“验证凭据”。
6. 验证成功后执行“激活凭据”，确认有效状态，再继续配置来源。

这些是上游 SDA 的登录信息，不是要求另设一个 MCChecker 操作 Token。MCChecker 的设置权限仍区分管理员和访客。

密码错误或账号锁定后，不要让任务反复尝试；更正登录信息，再按界面人工重试或更换。不要把密码、Cookie 或请求令牌写进来源名称、URL、备注或文档。

### 5.4 从目录选择目标资源

1. 添加更新来源，类型选择“SDA 文件”或“SDA 表”。
2. 选择刚配置并启用的连接。
3. 点击“从 SDA 目录选择”。
4. 在返回的目录条目中选择目标文件或表。
5. 系统自动填入资源引用和业务路径，核对名称及位置。
6. 选择接收目标、计划，点击“测试来源”。
7. 测试成功后保存，再手动执行一次更新并检查结果。

ID 和路径必须来自当前连接目录，服务端保存时会再次校验。目录为空时，先确认连接、凭据、资源类型和采集器状态；不要自行拼接 ID 绕过校验。

“SDA 目录”类型用于目录读取，不应把目录读取成功当成目标文件下载或参数表读取成功；日常更新具体配置，应选择 SDA 文件或 SDA 表。

### 5.5 保活、自动重登、自动更新各管什么

| 设置 | 作用 | 不代表什么 |
| --- | --- | --- |
| 连接保活 | 按间隔尝试维持上游登录会话 | 不代表已经验证真实网站的空闲续期能力 |
| 失效后自动账密重登 | 登录失效后用已保存的有效凭据重新登录 | 不会无限重试错误密码 |
| 工作区自动更新 | 按计划运行来源更新 | 不等于连接保活开关 |

保活间隔支持 1–60 整数分钟；这是配置范围，不是对真实 SDA 会话有效期的承诺。暂停自动更新不会自动关闭保活；反过来，保活成功也不会更新文件内容。

## 6. 接收目标决定更新之后发生什么

### 文件归档

选择已有目标文件，更新该文件并保留历史版本。适合“获取最新版配置文件，供查看或后续导入”。这一步不等于更新所有软件版本标准或机台参数。

### 默认配置候选

这是界面的目标类型名称，含义是：把变化送到指定配置、指定软件版本，先供用户核对。

1. 选中正确的配置和软件版本。
2. 执行更新。
3. 打开“待处理变化”，查看参数变化与冲突。
4. 按界面处理差异并写入草稿。
5. 在版本参数页面核对并保存配置。

获取更新、写入草稿、正式保存是独立步骤。候选不会自动替你保存正式配置，更不会直接下发机台；更新标准也不会自动改变全部机台。

### 机台实际值观测

这是特定的现场观测能力，不适合作为普通下载的目标。它需要可信设备身份及受支持的关联契约，不能根据文件名或 IP 猜测机台。本项目当前仍有相关外部/领域关联限制；遇到阻断应保留错误并由维护人员核对，不改用其他目标冒充采集成功。

## 7. 配置定时更新

确认至少一次手动更新结果正确后，再设置计划：

| 来源计划 | 行为 |
| --- | --- |
| 继承工作区计划 | 使用当前工作区的计划 |
| 自定义间隔 | 使用此来源的间隔，界面支持 1–2160 小时 |
| 仅手动 | 不按来源定时计划自动运行 |

还需要确认来源启用、连接可用，以及工作区自动更新未暂停。工作区暂停时不要以为设置了自定义间隔就一定会自动运行；手动更新仍可单独执行。

修改“工作区计划”会影响该工作区相关来源。执行全量更新前阅读确认范围：文件内“更新当前文件”覆盖这个文件的已启用来源，不受当前列表筛选影响；工作区全量更新覆盖更大范围。运行开始后切换页面，不会把任务变成新工作区的任务。

## 8. 两个完整场景

### 场景 A：从稳定下载地址更新一个配置文件

- 原系统提供稳定地址 `https://files.example.internal/downloads/MachineConfig.xml`。
- 目标是当前文件，不自动修改标准参数。

操作：打开目标文件 → 更新管理 → 更新设置 → 添加更新来源 → HTTP 文件 → 填下载地址 → 目标选“文件归档”和当前文件 → 仅手动 → 测试来源 → 保存 → 手动更新 → 查看运行详情和文件历史 → 确认正确后设置定时。

### 场景 B：SDA 参数表更新某软件版本的标准

- 原系统页面需要登录，目标资源能在 SDA 目录中找到。
- 目标是某配置的软件版本 691，先核对变化后保存。

操作：配置并激活 SDA 连接 → 添加 SDA 表来源 → 从目录选择表 → 目标选“默认配置候选”并选择对应配置和 691 → 测试 → 保存 → 手动更新 → 待处理变化 → 核对差异并写入草稿 → 打开 691 标准参数 → 核对并保存。

两种场景都不代表向真实设备下发配置。

## 9. 常见问题

| 现象 | 优先检查 | 处理方法 |
| --- | --- | --- |
| 浏览器能下载，来源测试失败 | 浏览器登录态、服务器网络、地址是否临时 | 找稳定文件地址；受支持的登录资源走 SDA |
| 返回 200 但仍报错 | 是否下载了 HTML 登录页或错误 JSON | 查看请求实际内容，修正来源，不能只看状态码 |
| SDA 目录没有条目 | 连接、类型、采集器、账号权限 | 修复连接后重新读取目录，不手填猜测 ID |
| 资源引用与路径不一致 | 是否复制了别的连接目录或手改路径 | 从当前连接目录重新选择 |
| 密码错误或凭据锁定 | 上游账号状态、密码、登录页面变化 | 人工修正后验证，不重复自动提交错误密码 |
| 测试成功但没有新文件 | 是否只点了测试、是否保存、是否真正更新 | 保存来源后手动更新，查看运行记录 |
| 更新成功但标准参数未变 | 目标是否为文件归档或候选 | 候选需核对、写入草稿、正式保存 |
| 显示内容未变化 | 上游内容是否与现有目标相同 | 通常无需重复生成版本；核对所选资源 |
| 定时不执行 | 来源启用、仅手动、工作区暂停、连接状态 | 分层检查计划和连接；不要只改保活间隔 |
| 保存提示被别人修改 | 其他管理员同时修改了来源 | 保留输入，核对服务端最新值后再保存 |
| 文件太大、超时或压缩包匹配失败 | 文件大小、网络、匹配规则、压缩内容 | 查看运行详情，缩小或修正来源；不要绕过限额 |
| 重新打开地址显示不完整 | 来源列表对 URL 查询参数有脱敏 | 不要把脱敏显示当完整请求；修改前核对原始受控来源 |

普通 HTTP 请求失败不会触发 SDA 自动登录。手动修改来源后，下次更新才使用新设置；保存失败不能当作已经生效。

## 10. 配置完成后的验收清单

- [ ] 工作区、机型、文件和目标软件版本正确。
- [ ] 使用真实文件下载来源，或当前连接目录中选择的 SDA 资源。
- [ ] 未把预览页、登录页、blob 地址、cURL 或 HAR 当作下载地址。
- [ ] 来源测试通过，且已保存设置。
- [ ] 手动更新已完成，并查看过运行详情。
- [ ] 已按接收目标核对文件历史或待处理变化。
- [ ] 若需要改变版本标准，已单独核对并保存；没有误认为会自动更新机台。
- [ ] 首次成功后才开启定时，并确认工作区计划范围。
- [ ] 来源信息和提交到 Git 的文档不含账号密码、Cookie、签名或真实业务内容。

## 11. 当前能力与外部限制

本教程按当前前端来源编辑器、来源测试服务和采集适配器编写，不包含未实现的任意网页解析、cURL 导入、自定义 POST 请求编排或通用登录录制。

SDA 真实环境的登录表单、接口协议、受保护资源权限和空闲保活，需要部署方提供并完成适配验证。本项目已有自建模拟环境验证，不能据此宣称任意真实 SDA 网站、真实设备或 Windows/Linux 环境已经验收通过。
