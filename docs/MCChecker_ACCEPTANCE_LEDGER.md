## §16.3–16.8 非功能项现状（同一口径：卡落地 ≠ 已验收）

- **16.1 四层命令**：pytest 与前端 HTTP 页面均已反复执行（当前集成分支连续三次 1852 passed、前端 `ALL PASSED (44)`）；**`bench_api.py --samples tests/fixtures/perf` 这一层目前以退出码 1 收尾**，因为 §7.3 与 R13 的矛盾（B10.1）已裁定归 M3-17，未闭合前 M4-08 不能把性能层记成通过。
- **16.3 接口级权限**：每卡都有四角色用例，但 M4-08 仍须自己点验收于"**403 时文件 sha 不变**"这一条，且统一写接口清单已由 `tests/test_api_revision.py::WRITE_ROUTE_EXPECTATIONS` 对账（29 条），四角色与 403 sha 不变仍由各卡用例执法。
- **16.5 数据兼容**：**完全未验证**。要求"脱敏旧 `data/` 副本能被新版读出、新版写入后 v1.0.1 + Python 3.12 仍能读回"。没有真实脱敏副本就必须标未验证，**不得拿空目录冒充通过**。这是当前最大的单点缺口。
- **16.6 Python 版本**：3.9.11 下 pytest + compileall 每卡都跑；`check_py39.sh` 不覆盖 `tests/` 与 `scripts/`，引用它时必须同时给出所用解释器。
- **16.7 离线**：发布卡只被允许声明"产物内无可抓取外部主机引用"，**物理断网 + 浏览器网络面板那一步至今未做**（记为待人工）。另有一条硬前置：M4-07 改完手册/README/requirements 后**必须重跑打包**，否则这一节的证据是旧快照。
- **16.8 安全**：响应头与跨站写保护已合并（含 501/414 旁路补口）；仍记两条未覆盖——协议版本本身无法解析时标准库不发头（协议决定），以及工具 URL 保存的拒绝需等 `/tools` 落地（M3-15）。
