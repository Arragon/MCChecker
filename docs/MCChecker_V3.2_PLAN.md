## 关键实现边界

- 使用原生 JavaScript、既有 tokens/modal/按钮和 Python 3.9 标准库；没有复制原型内存模型或引入运行时依赖。
- `config-files`、`config-standards`、`config-machines` 和 `parameter-query` 投影现有文件/配置数据，不建立平行存储。文件删除后同名重传的新身份不接管旧历史。
- 软件版本标准取本版最新已保存记录，不取全局 head；初始参数身份与手工标准分开。机台升级草稿的目标版本不改变正式归属。
- 保存是顺序编排草稿 PATCH 与原正式保存接口，不宣称跨请求原子事务；部分成功保留已完成草稿，结果不明先读回，正式保存使用稳定请求回执。
- 机台升级通过既有 merge-plans 的 machine_id 模式捕获来源/目标/模式/草稿身份；只更新该会话草稿，不发布。通用标准合并仍保留。
- 显式放弃草稿使用 ID、修订和回执；未保存新版本若被后续版本、机台或更新来源引用，拒绝移除并说明原因。锁顺序为工作区同步锁 → 配置锁。
- 候选的原来源继续使用不可变来源文件版本；正式值和当前标准草稿分别展示。预览编辑指纹及提交写锁避免比较旧值后覆盖新草稿。
- 候选 `review_state` 只是只读投影：写草稿后待保存，正式值与来源相符后才移出待处理；原候选状态机不改。HTTP 重试先识别回执再核对预览。
- 新运行保存可选 `frozen.source_targets`。旧运行没有可证明文件归属时只留在工作区历史，不能通过今天的来源重新绑定推算过去。
- 来源创建、认证、连接保活、计划与运行继续使用真实服务。用户指定模拟 SDA 联调；模拟结果不代表真实 SDA、目标设备或 Windows/Linux 实机验收。
