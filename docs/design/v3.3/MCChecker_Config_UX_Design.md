## 目标与当前边界

用户打开配置文件，先看到贯穿软件版本的基线主线与机台独立轨道，选中一个保存节点后查看参数、比较、详情或导出。参数表是独立标签，编辑后仍直接核对保存；需要协作时再提交评审。机台与参数入口使用同一组文件、记录和来源，常用操作不要求先理解 Git 术语。

| 层次 | 本轮依据与状态 |
| --- | --- |
| 已有能力 | 真实服务已有配置文件身份、软件版本、Bn/rn 保存、草稿并发检查、三方比较、来源更新、历史与导出；不能把它们全部描述为待从零开发 |
| 本轮设计 | 文件详情默认版本路线图、独立参数标签、人可读记录名称、明确多选范围、必填修改原因、可选关联链接，以及跨文件机台/参数视图 |
| 原型模拟 | 独立页面以示例数据演示交互；源码不接生产服务，网络抓取、权限、持久化和规模能力不能由演示证明 |
| 未来生产实现 | 数据迁移、真实 API、保存一致性、采集适配与性能测试按实施计划推进，目前未完成 |

## 信息结构与用词

界面使用“配置文件、版本路线图、版本基线、机台、保存记录、待评审、查看来源”。所有记录用人可读全称，例如“版本基线 · 软件 691 · 第12次保存”或“MC-001 · 软件 691 · 第3次保存”。软件版本和保存次数分别表达，节点、选择器、比较表和导出说明都不用 Bn/rn 作为唯一名称；内部 ID 与旧 label 继续兼容。

| 入口 | 默认工作区 | 主要动作 |
| --- | --- | --- |
| 配置文件 | 可搜索的文件列表，显示软件版本、当前记录和待处理状态 | 打开、初始化；勾选后出现批量动作 |
| 单个配置文件 | 版本路线图：基线主线、机台轨道、记录行及真实父关系 | 选节点后查看参数、比较、详情或导出 |
| 文件内参数标签 | 所选标准或机台的精确保存记录参数表 | 编辑、核对保存、查看参数来源；历史只读 |
| 机台 | 这台机台使用的全部配置文件及各自记录 | 打开文件、核对采用标准、导出配置包 |
| 参数 | 选择一组参数和有限的保存记录列 | 查更名、属性和值变化，返回对应文件 |
| 待评审 | 自己提交或需处理的变更 | 查看差异、讨论、批准或请求修改 |
| 更新管理 | 来源、待核对更新、获取记录 | 添加链接、获取更新、核对候选；高级规则折叠 |
| 操作记录 | 当前范围内可筛选的事件 | 查看差异、来源、操作者与相关记录 |

配置文件、机台、参数是观察同一数据的三个入口。跨文件机台使用稳定身份绑定，不能靠同名自动合并；同名参数在不同文件中也不自动成为同一参数。

## 布局与视觉

延续现有浅灰页面、白色数据区、蓝色主要动作与中文系统字体；成功、危险、修改和绑定沿用现有语义色。复用既有按钮、字段、图标、弹窗及文件标题组件。精致度来自对齐、节奏和清楚的状态，避免无信息副标题、重复摘要和大面积装饰。

顶部固定工作区和配置集；文件标题、软件版本、当前标准或机台及保存记录形成紧凑上下文。路线图或参数表占据主要工作区，内容局部滚动，必要轴/表头和操作保持可达。参数目录可收起，详情按需打开；不同时常驻多块侧栏挤压主要内容。

版本路线图是文件详情的默认工作区。基线保持一条跨软件版本主线，每台机台有独立轨道；记录行将节点、完整名称、修改原因、作者和时间对齐。分叉、采用和合并连线来自真实 `parentIds`/来源引用，不用软件版本分组位置或时间邻近关系造线。未知或未载入父节点明确标识，选中节点后的操作始终绑定该精确记录。

组织方式参考 [GitKraken Desktop 官方界面说明](https://help.gitkraken.com/gitkraken-desktop/interface/)中的图、记录信息和选中详情配合：采用其信息组织思路，继续使用 MCChecker 的色彩、控件和中文风格，不复制商业素材或代码。路线图支持局部双向滚动和有界记录窗口；“聚焦机台及来源”仅显示该机台及真实祖先/采用关系，收拢可见轨道，“全部配置”恢复完整图。聚焦保留原始节点和边的身份，不新建父边；参数标签保留高密度表格。

窄屏让工具栏回流，目录与详情转为可关闭面板；宽表在自身容器横向滚动，保留可读输入宽度。主要动作和返回入口不能被裁切。所有图标按钮有可访问名称，状态同时使用文字，键盘焦点可见，弹窗关闭后焦点回到触发处。

## 关键流程

| 场景 | 交互顺序 | 保存结果与约束 |
| --- | --- | --- |
| 第一次管理文件 | 选文件 → 预览参数 → 确认软件版本与原因 → 建立版本基线 | 有真实原始输入才建立初始快照；手工填写不冒充原始数据 |
| 查看文件历史 | 打开路线图 → 选保存节点 → 查看参数/比较/详情/导出 | 完整名称、原因、作者和时间对应同一精确记录 |
| 日常改参数 | 选节点或参数标签 → 编辑 → 填原因并核对保存 | 产生不可变记录；直接显示目标和差异，默认不要求评审 |
| 协作修改 | 编辑 → 提交评审 → 讨论/批准 → 核对保存 | 评审针对固定内容；策略启用时要求独立批准，内容改变需重新核对 |
| 新建机台配置 | 选择机台和软件版本 → 确认采用标准 → 编辑/保存 | 采用精确记录；多文件页面汇集同一机台绑定 |
| 机台采用新标准 | 选目标标准 → 比较原标准/当前配置/新标准 → 处理冲突 → 核对保存 | 固定值保留；不会自动改变其他文件或物理设备 |
| 合并修改 | 选来源和目标 → 核对共同起点 → 处理差异 → 草稿 → 核对保存 | 来源/目标变化后旧计划失效；无可信起点不伪造自动合并 |
| 比较 | 选一个保存记录或本地文件 → 查看差异 | 更名、属性和值分别显示；外部文件不会因比较直接写入 |
| 添加/修改更新来源 | 粘贴链接或改设置 → 识别并预览 → 核对接收文件与原因 → 保存来源 | 规则、映射、连接或调度设置的保存都记录用户原因；修改提取输入使旧预览失效 |
| 多文件更新 | 获取更新 → 查看逐文件结果 → 核对选中项 → 保存 | 失败/无变化/未选中分别显示；逐文件提交，不承诺整批原子生效 |
| 查来源 | 参数行“查看来源” → 字段来源与相关记录 | 区分原修改者和本次采用者，缺少证据显示未知 |
| 恢复 | 打开历史记录 → 以此创建草稿 → 比较 → 核对保存 | 新增保存记录，旧历史不变；仍可自选提交评审 |
| 导出 | 选择确定记录 → 核对模板/文件清单 → 预览 → 导出 | 单文件保留模板语义，多文件带清单；缺文件不能假装完整成功 |

“核对保存”展示真实改变的行、接收对象、来源、必填修改原因和可选关联链接。所有实际内容或配置设置的提交都必须有用户填写且去除首尾空白后非空的原因，包括初始化、新建软件版本/机台、来源设置、合并与恢复；系统操作说明不得代填。无差异不生成空记录。浏览、筛选、选择、比较或单纯获取来源不要求另填修改原因。

关联链接可逐行填写，保存为规范化、去重的 HTTP(S) 绝对地址；拒绝危险协议、不完整地址、账号密码和控制字符。记录详情、评审与操作记录中可点击打开，按安全外链方式渲染；示例 `.invalid` 地址标明演示。评审的原因和链接随提交内容冻结，合并原样传播。旧历史缺少原因时显示“原因未记录”，原 `message` 作为历史说明保留，不补造原因。

评审、来源高级规则和详细审计信息按需展开。完成任务必需的字段、错误和不可逆后果直接显示，不藏进 Tooltip。查看历史时标题明确“历史只读”，编辑动作替换为创建草稿，不能让控件看起来可以原地改历史。

## 状态与恢复

| 状态 | 用户看到什么 | 可采取的下一步 |
| --- | --- | --- |
| 尚无文件/尚未初始化 | 简短原因与单一初始化入口 | 选择真实文件或开始手工定义 |
| 搜索无结果 | 保留搜索条件，说明没有匹配项 | 清除或修改条件，不当作数据被删除 |
| 加载/处理 | 局部进度，已显示上下文不跳动 | 取消可取消操作；完成前阻止重复提交 |
| 有未保存修改 | 已改项数和可见保存动作 | 继续编辑、放弃本次修改、暂存并离开 |
| 校验/保存失败 | 错误定位到字段或文件，输入仍保留 | 修正或重试，不以成功提示掩盖失败 |
| 原因为空/链接无效 | 标明原因字段或具体链接，保留全部输入 | 修正后重试，不自动生成“保存配置”等原因 |
| 服务器内容已变化 | 编辑前、服务器最新、本次修改 | 按字段核对，独立修改保留，重新保存 |
| 待评审/待修改 | 当前提交版本、未解决讨论、下一动作 | 修改后新提交，旧评论保留且标明过时 |
| 历史只读 | 保存时间、精确采用标准和来源 | 比较、导出、创建草稿 |
| 需要登录/未识别 | 真实错误及连接/规则入口 | 选连接、重试或手工设置，不无限自动重试 |
| 批次部分失败 | 每个文件的结果与选中范围 | 重试失败项或明确接受子集 |
| 访客 | 已有查看能力与当前身份 | 写操作不可用，服务端仍检查权限 |
| 来源不完整 | 明确哪些字段未知 | 查看现有证据，不补造作者或原始值 |

切换工作区/配置集时先处理未保存输入，再清除旧选择、上传内容、计划和候选。异步响应必须匹配发起时的范围；不能把旧工作区的结果显示或保存到新工作区。

## 3000+ 参数与多文件

生产查询在服务端针对全量数据搜索和筛选，再返回分页结果。路线图只布局必要记录窗口并保留真实父节点的边界引用；表格仅渲染当前行窗口，多参数历史只请求选定记录列。文件、机台、保存记录都采用有界查询，目录、字段详情和长来源链按需加载。

多选同时提供“本页全选”“全部筛选结果”“清空”，跨页按稳定 ID 保持。显示已选总数及其中“筛选外 N 项”，筛选变化不悄悄丢弃这些选择；表头勾选反映本页全选/半选/未选状态。执行前再次核对范围。参数选择器和来源文件预览也有明确全选/清空操作；来源预览只选择已列出的已验证文件。比较最多选择 6 条记录，其批量按钮写“全选最近6条”，不能暗示无上限全选。

规模验证使用 3000+ 参数并组合多文件、多机台、长历史，在相同环境比较改造前后。记录首批显示、可交互时间、搜索/翻页、DOM、长任务、内存、请求量和服务端读取次数。取得基线后确定预算；原型样本、分页外观和既有测试脚本不证明生产性能已经达标。

## 原型检查点与验收

本轮原型迭代覆盖默认路线图与 `versions` 兼容、节点上下文、人可读名称、选择范围、原因/链接，以及已有初始化、直接保存、评审、合并、更新、恢复和导出。当前模型 38/38、来源模块 69/69、路线图 10/10、UI 28/28 检查通过，共 145 项，实际输出见 [验证记录](VERIFICATION.md)。UI 检查采用 Node VM 与 DOM 替身，先前界面结果不充当本轮通过证据。

原型只演示浏览器内数据与行为。来源样例不会抓取真实网页；简化 XML/JSON 处理不代表生产保留格式或安全解析；身份切换不代表生产鉴权；内存中的并发示例不代表磁盘事务。刷新还原、样例限额与真实文件处理范围在原型相应位置说明。
