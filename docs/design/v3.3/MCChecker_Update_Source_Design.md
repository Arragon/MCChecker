# MCChecker 更新来源设计

状态：V3.3 设计与交互原型；网页发现、列表提取与大文件改造尚未接入生产。核对日期：2026-11-11。代码依据：分支 `codex/v32-prototype-parity-20261109`，提交 `d19ee3e8f896a089a2d8eb5628c0e8bb9b18a0de`。

目标是让普通来源保持“粘贴链接 → 识别预览 → 保存”，让获取到的文件先成为可核对的变化。界面使用“更新来源”“提取规则”“文件对应关系”“测试结果”，工程对象名称只用于本文的实施说明。获取、写入草稿、保存配置和向设备下发是不同操作；本次来源功能不向设备下发。

## 页面与日常流程

普通链接先只显示地址输入框、“识别并预览”和样例/帮助入口。识别完成后直接出现文件对应表，用户核对接收配置并保存。来源名称可自动带出并编辑；更名、调整频率不必重新下载测试。提取设置变化时旧结果立即失效，保留用户输入并清除可操作的旧预览。

“手动设置提取规则”“通过要素组成地址”“自动更新设置”默认折叠。用户不需要理解适配器、选择器语言或任务编排才能完成普通单文件来源。识别失败在原位置说明失败阶段与下一步：修正地址、重新登录、指定列表位置、使用稳定下载地址，或选择已支持的连接。

多个文件使用紧凑表格，列为来源文件、格式/大小、接收配置、目标版本、检查结果；包内路径作为文件名下的次级信息。提供搜索、类型/状态筛选、勾选、批量接收位置和分页。全选必须区分“本页”与“筛选结果”，操作范围显示选中数量。文件名和版本不能依靠悬停才能辨认。大结果不会创建数百张卡片或一次渲染全部行。

测试结果固定区分“已检查”“未检查”“失败”。如果只取前 N 个文件或前 N 页，展示实际覆盖范围、截断原因及未检查数量；未知总数写“总数未知”，不将样本通过展示成整批通过。正式运行的完整结果按文件分页，不在表格单元格中展开整个文件内容。

保存来源后可手动“获取更新”。运行记录给出文件数量、变化数量和失败文件；“待核对”进入具体配置的差异，载入草稿后仍需普通保存或提交评审。定时任务只获取并生成待核对内容。普通修改可直接核对保存；需要协作时使用现有评审与评论，不对所有更新强制增加审批步骤。

## 自动识别能判断什么

识别依据应来自响应头、有限响应片段和结构证据，扩展名只作提示。单文件需检查 XML/JSON 格式与目标配置结构；HTML 需找到实际下载链接；JSON/XML 需找到一组具有下载地址和名称的记录；压缩包需根据签名识别格式并列出受支持成员。响应 200 仍可能是登录页或业务错误。

识别结果说明理由，例如“找到 12 个 XML/JSON 下载链接”或“检测到 ZIP 文件”。同时出现多个可用清单时，让用户选择具体位置并预览；信息不足时显示“需要补充规则”，不编造成功率或自动宣称适配完成。只有少量安全、确定的候选进入有限探测，不遍历整站。

纯 JavaScript 渲染页面、浏览器 `blob:` 下载、复杂多步骤导出、SSO、验证码与未知登录流程不属于通用静态识别承诺。可用路径是稳定下载接口、用户填写提取规则或已实现的受支持连接。不得尝试绕过验证码，也不能将现有 collector 的受限适配包装为通用浏览器采集能力。

## 内容格式与提取规则

| 来源 | 自动预览 | 手动输入的明确语法 | 生产处理边界 |
| --- | --- | --- | --- |
| 直接 XML / JSON | 文件名、结构摘要、参数数目、目标结构是否相符 | 通常无列表规则；必要时选择已有模板 | 使用已有配置模板解析，不把 JSON 清单误当参数文件 |
| HTML 下载列表 | 普通链接、可读文件名、相对地址解析结果 | 支持文档化的 CSS 子集：标签、`#id`、`.class`、后代关系与属性存在/等值匹配；例 `#downloads a[href]`。下载字段为 `href` 等允许属性，名称可选文本或属性 | 不执行脚本；相对链接以最终响应地址解析，每个结果再次检查下载策略 |
| JSON 文件清单 | 含下载地址/名称字段的记录数组 | 列表位置用 JSON Pointer，如 `/files`；字段位置相对每条记录，如 `/downloadUrl`、`/name`；支持标准 `~0`、`~1` 转义 | 数组用于文件清单，不等于示例参数导入支持所有数组结构；不运行任意表达式 |
| XML 文件清单 | 重复记录元素及链接属性/子元素 | 受限相对路径，如 `./files/file`、`.//file`；字段为 `@href` 或子元素路径；命名空间前缀通过显式表对应 | 不支持外部文档函数、自定义函数或脚本；使用已审查的 XML 解析配置 |
| ZIP / TAR / TAR.GZ / 单层 gzip | 规范化包内路径、类型、大小、重复名 | 包内匹配单独使用明确的 glob 规则；多个规则分号分隔；旧正则另保留兼容标记 | 既有格式能力继续复用；不默认递归解开任意嵌套压缩包 |

这些是目标规则契约，尚非已接入的服务端接口。CSS/JSON Pointer/相对 XML 路径需要各自校验和友好报错，不合并为一个“万能表达式”。ElementTree 官方明确仅提供有限 XPath 子集，本设计据此限定语法，不承诺完整 XPath。[4]

地址模板独立于内容提取，只替换已声明字段，例如机型、软件版本和文件名；按路径段或查询参数所在位置分别编码。预览显示最终地址并脱敏，不允许任意 JavaScript、Python、Shell 或整段 cURL。需要 POST 导出任务或专有认证协议时，进入已知连接的适配工作。

## 分页、空间与性能

列表分页支持“下一页链接”“响应中的下一页字段”或明确页码参数。每次运行固定最大页数、条目数、请求次数、累计下载字节、累计展开字节、并发量和总截止时间；达到任一上限即停止，并记录已覆盖范围。下一页需落在受控网络范围，循环地址或重复游标会终止，分页不重置累计预算。

下载按块写入受控临时文件，同时累计大小与哈希。单文件先完整下载、校验并建立候选，再替换其有效内容引用；异常、取消、磁盘不足清理未完成临时文件。解析使用受限迭代或流式处理，尽可能及时释放已处理元素；仅换成 `iterparse()` 而把所有参数和原文再次收集到列表仍不能保证内存有界。前端只收到分页摘要和按需差异。[代码：`collector/stream_reader.py`、`app/core/downloader.py`]

压缩包需要可寻址读取时允许在受控目录临时落盘。逐成员处理时只维持有限的读取、解析与暂存窗口，不保留“压缩原文 + 全部展开成员 + 全量参数 + UI 全部行”的多份内存副本。临时空间预算、保留内容配额、历史清理和取消恢复都属于同一次任务的资源管理。配置容量来自部署策略，不能为了通过测试静默扩大限额。

在配置文件数多时，文件对应关系采用服务端筛选和分页；批量提交使用稳定文件 ID，不通过当前表格行号定位。来源没有变化时复用内容哈希与已登记版本，避免重复保存相同原文和候选。压缩包按内容拆出共享原文时允许内容寻址去重，但规则版本、运行和采用记录仍分别保留。

## 文件对应关系与逐文件提交

来源文件身份应优先来自受支持接口的稳定资源 ID；其次使用规范化清单路径或包内完整相对路径。显示文件名不能作为唯一键。临时签名参数只有在已知协议明确标记为易变时才从身份计算中排除；不能任意删除查询参数，导致两个不同资源被误认为同一文件。

每个选中文件对应一个工作区内的稳定配置文件 ID 和目标分支/版本。多个来源文件对应到同一目标时阻止保存；如果业务确需组合文件，应另行定义组合模板，不使用“后一个覆盖前一个”。同名、大小写、Unicode 规范化、文件名裁剪和包内路径扁平化的冲突都要在预览中指出。

一次任务冻结工作区、来源版本、规则版本、连接引用、发起人和全部对应关系。切换页面不改变任务归属；同来源重复点击复用同一进行中任务。候选内容带目标保存记录 ID，载入草稿与最后保存都核对该 ID，目标已变化时保留输入并要求重新比较。

逐文件处理结果可以成功、无变化、失败或跳过，整批可部分成功。成功文件生成自己的内容版本和候选，失败文件保留此前有效内容与比较起点，不把失败标成“无变化”。已有 `commit_fetch_result()` 在原文件落库后候选登记失败时返回部分失败；新设计必须继续保留这一事实，后续重试仍使用原比较起点。

来源变化比较应同时考虑“上一份确认的来源内容”“当前配置/草稿”“新来源内容”。Argo CD 的 Legacy 策略明确使用 live、desired 与 last-applied 三方信息；这里只借用保存比较起点的原则，不引入其控制器或 Kubernetes 数据模型。[2]

## 内网、凭据和不可信内容

MCChecker 是内网工具。继续使用既有 `DownloadPolicy` 的主机/IP/CIDR、连接信任与禁止规则，不能全面拒绝私有地址而破坏已授权内网来源。当前 `allow` 为空有既定含义，变更默认网络策略应独立评估；任何自动发现不能自行扩大范围。每个重定向、列表链接和分页地址都重新检查策略，凭据不能被跨站重定向带往未授权主机。

签名链接、Cookie、Authorization 和原始连接凭据不出现在表格完整地址、错误文本、导出记录或审计事件中。界面展示脱敏地址；长期任务优先使用稳定入口与受控凭据引用。需要暂存敏感 URL 时使用现有凭据/秘密存储边界与失效时间，不写入普通日志或规则样本。采集器持有登录会话，应用侧只保存必要状态和引用。

压缩包不要调用无筛选的整包解压。路径拒绝绝对路径、`..`、驱动器/UNC、NUL 和目录逃逸；拒绝或明确跳过符号链接、硬链接与特殊文件，ZIP 也要检查成员元数据。文件数约束覆盖全部成员元数据，展开字节同时限制单文件和总量，压缩比只作辅助。现有 64 个配置成员限制不是完整压缩炸弹防护，更不意味着 ZIP 已全面处理符号链接。

XML 清单和参数文件解析均禁用外部实体、外部资源及 DTD 扩展，并测试编码、深度、实体膨胀和体积边界。不能仅依赖某条文本正则判断所有编码。保留生产模板的属性、命名空间和精度语义；遇到无法确认的结构先拒绝或要求模板，不能安静地丢掉字段。[4]

## 规则版本、测试与过期结果

工程层建议记录来源定义、提取规则版本、对应关系版本、连接引用和测试证据；内部可称 `SourceRecipe`，界面仍称提取规则。名称或频率变化与提取语义变化分开：前者保留有效候选，后者让旧测试和旧候选失效。保存时通过来源版本检查并发修改，运行时固定所用版本。

测试证据关联输入指纹、规则版本、目标结构、连接版本、样本时间、命中数量与覆盖范围。任何影响提取的输入变化，立即清除旧可操作预览；保存接口再次校验，不只禁用按钮。异步测试使用请求序号和编辑上下文，离开页面、切工作区或新测试开始后，晚到结果不能覆盖当前表单。

规则可以附带脱敏的小样本用于离线复测。样本明确保存期限、体积与权限，不复制完整受保护网站。与上次结果相比，格式变更、清单突然为空、数量骤变、必需字段缺失、落到登录页等均为“规则可能过期”的证据；“零结果”不能自动意味着应删除全部配置。

审阅通过应绑定具体差异和目标起点。GitHub 受保护分支文档允许在差异或合并起点变化后使旧批准失效；本项目在启用评审的路径上采用相同原则，避免旧通过状态授权新的内容。[1]

## 操作记录与回溯

每次来源设置、测试、获取、解析、候选生成、载入草稿和正式保存都能关联到工作区、发起人、来源版本、规则版本、文件身份、内容哈希、目标保存记录和结果。参数归属进一步链接到本次采用的来源文件/字段、评审讨论和保存原因；参数更名依靠稳定参数 ID 与明确映射，不靠名称相似度自动断定。

运行详情同时呈现成功与失败文件，可仅重试失败项。查看当时内容读取保存的不可变版本；“用当时内容重新生成候选”与“现在重新获取”明确分开。重新生成候选不自动覆盖目标，也不重新触发未经请求的外部操作。

NiFi 官方的 provenance 记录事件当时的属性、内容及父子关联，并提供从保存内容重放的入口；本项目借鉴这些证据关系，不引入完整 NiFi 服务或流程设计器。[3]

## 本次可运行原型与调用约定

`prototype/sources.js` 是独立 UMD 模块，浏览器名为 `MCPrototypeSources`，Node 可直接 `require`。不依赖 UI DOM，不调用网络，不保存凭据，不包含定时执行器。识别只接受 `.invalid` 样例；HTML、ZIP、JSON/XML 清单结果明确为模拟条目，手动提取规则只保存并用于失效判断，未真正执行网页提取。ZIP 解包演示不等于已有生产 ZIP 能力需要重做。

本地参数样本由独立、严格受限的解析器处理：上限 5 MB、10,000 参数、32 层、单个数值文本 4,096 字符。JSON 仅支持非空对象中的数值、文本和布尔值；数组、null、空对象、重复键、空键、含 `/` 的键与保留名明确拒绝。XML 仅支持简单元素，拒绝属性、命名空间、同名兄弟、混合文本、DTD、注释、CDATA 和处理指令；保留支持的叶文本、标准字符实体、根名称和精确数字文本。JSON/XML 输出是通用示例，不可替代正式模板导出或直接用于设备回写。

数字参数的 `value` 在可精确表达时使用 Number，否则保留字符串；`type` 仍为 `number`，`rawNumeric` 保留原数字写法。导出只有在当前值与原值一致时才复用该写法，编辑后使用新值。任意精度数值不能先经过 `Number()` 再声称保真；根标量、路径前缀覆盖与不支持结构均拒绝。

| API | 约定 |
| --- | --- |
| `parseText(text, name, reference=[])` | 返回 `name, format, rootName, params, matched, unknown, sampleOnly`；按字段路径复用参数 ID |
| `serialize(params, format, {rootName}?)` | 返回完整 XML/JSON 文本；拒绝重复/前缀覆盖路径、无效值与不兼容 XML 名称 |
| `numericValue(raw)` | 返回精确可表达数值、需保留的数字字符串或 `null`；不代表完整生产校验 |
| `sampleDraft(kind, target?)`、`composeUrl(template, values)`、`redactUrl(url)` | 五类样例、地址模板和安全展示；模板仅支持 `model`、`version` |
| `create({getFiles, getHead, getActor?, onEvent?, delayMs?, now?, seed?})` | `getFiles(wid)` 提供文件/分支；`getHead(wid,fileId,branchId)` 提供 `id,label,params`；来源默认空；可按工作区提供 seed |
| `list/get/listRuns/draft` | 工作区显式入参，返回副本；不让 UI 直接改内部状态 |
| `fingerprint(wid,draft)`、`invalidate(contextKey?)`、`detect(wid,draft,{contextKey,signal}?)` | 默认上下文 `source-editor`；提取输入/页面/工作区变化需 invalidate；识别返回绑定工作区与指纹的演示预览 |
| `save(wid,draft,preview,{actorId}?)` | 再校验测试、来源版本、文件身份与目标冲突；保存规则和逐文件对应关系；更名/频率变化保留候选 |
| `run(wid,id,{actorId,signal,fail,failPaths}?)` | 同工作区同来源去重；冻结发起人，始终写原工作区记录；支持完整失败/部分失败示例并保留有效内容 |
| `candidates(wid,id)`、`toDraft(wid,id,candidateId)` | 每个文件各有候选；载入前检查目标 head；只返回草稿，不修改模型 |
| `markApplied(wid,id,candidateId,savedRevisionId,{actorId}?)` | UI 实际保存模型后调用；只在保存记录和值吻合时清除该候选，不因载入草稿就清除 |

预览带 `workspaceId, fingerprint, kind, mock, rulesExecuted, testedAt, files, sampled, total, limits, message`。文件行带 `key, path, name, format, count, selected, target, branchId, status, message`。来源带 `version, ruleVersion, rules, mappings, pending`；候选带 `sourceId, fileId, branchId, headId, params, changed`；运行记录带 `actorId, status, files, changed, errors, mock`。运行状态为 changed、unchanged、partial、error 或 cancelled，UI 应翻译为简洁中文。

`verify_sources.cjs` 从 `prototype/sources.js` 读取实际模块，使用真实 JSON/XML 文本与内存文件快照，运行命令为 `node --test docs/design/v3.3/verify_sources.cjs`。本轮重建首次与 repo 副本复跑均为 69 项通过；不是以前环境的测试结论，也没有浏览器、真实站点、生产性能或生产模板验收含义。后续 UI 整合与独立测试需另行报告。
